### 목표 (사용자가 직접 말한 것)

- **게임 개발 업계 표준과 요즘 방식**을 함께 다룬다. 옛날 방식만 설명하고 끝내지 않는다.
- **인터랙티브 위젯**으로 이해를 돕는다. 특히 자료구조·알고리즘처럼 그림과 조작이 있어야 이해되는 주제.

## 2. 절대 규칙 (어기면 안 되는 것)

1. **중복 서술 금지.** 한 개념의 정의와 원리는 **정확히 한 챕터에만** 둔다.
   다른 곳에서는 `<span class="seealso">`로 링크만 건다. 두 곳에 쓰면 반드시 한쪽이 낡는다.
2. **챕터 하나 쓰고 사용자 확인을 받는다.** 여러 챕터를 한 번에 쓰지 않는다.
3. **한 세션에 다 하려고 하지 말 것.** 사용자가 명시적으로 요청한 사항이다.
   세션이 끝날 것 같으면 이 문서를 먼저 갱신한다.
4. **단계별로 git 커밋한다.** 저장소에 올릴 예정이므로 "챕터 1개 = 커밋 1개" 정도의 단위로 남긴다.
5. **웹서칭으로 교차검증한다.** 내 코드/기억과 실제 최신 사실이 다를 수 있다.
   특히 버전이 붙는 것(Unity API, C++ 표준, 컴파일러 동작)은 **반드시 공식 문서를 확인**하고,
   챕터 하단 「확인한 출처」에 링크를 남긴다.
6. **기존 md 5개와 `면접정리예제/`는 지우지 않는다.** 리서치 원본으로 유지하고 링크만 건다.

3. 설계 축/분류  같은 문제의 여러 해법을 축으로 정리
4~n. 심화       필요한 만큼
n+1. 요즘은 어떻게 하는가 — 업계 표준과 Unity   ★ 반드시 있어야 함

## 4. 파일 구조와 손대는 법

```
교안/
  00_인수인계.md          ← 이 문서
  index.html              메인 허브
  quiz.html               기존 퀴즈 페이지 연결(추후 흡수)
  assets/
    site.js               ★ 전체 목차 데이터(SITE 객체) + 헤더/목차/이전다음 렌더링
    style.css             공통 스타일
    widgets.js            ★ 인터랙티브 위젯
  study/                  20개 챕터
  interview/              면접 204문항 (미착수)
  projects/               내 코드 사례 (미착수)
```

- **`file://`로 열리므로 `fetch`/JSON을 쓸 수 없다.** 데이터는 전부 `site.js`의 전역 `SITE` 객체에 둔다.
- **챕터를 완성하면 `site.js`에서 그 챕터의 `status`를 `"todo"` → `"done"`으로 바꿔야** 허브 카드가 활성화된다.
- 진도/테마는 `localStorage`(`gyoan.progress.v1`, `gyoan.theme`)에 저장된다.
- 챕터 페이지의 사이드 목차·이전/다음은 자동 생성된다. `<body data-chapter="c2">`만 맞춰주면 된다.
- 새 챕터 HTML은 `study/`의 스텁 파일을 그대로 채우면 된다(헤더/푸터 마크업이 이미 들어 있다).
  위젯을 쓸 경우 `<script src="../assets/widgets.js"></script>`를 `<head>`에 추가한다.

### 위젯 추가하는 법
`assets/widgets.js`의 `WIDGETS` 객체에 함수를 하나 추가하고,
본문에 `<div class="widget" data-widget="이름"></div>`를 두면 끝이다.
`widgetShell()`이 제목/설명/본체/조작부/상태줄 껍데기를 만들어준다.

현재 있는 위젯:
- `pool` — 오브젝트 풀 시뮬레이터 (슬롯 대여/반납, 힙 할당 횟수 비교)
- `alignment` — 슬롯 크기 슬라이더로 메모리 정렬이 깨지는 걸 직접 보기

## 8. 이미 확인한 사실 (다시 검색하지 말 것)

### C-2에서 교차검증한 것
- **MSVC는 기본적으로 `operator new` 뒤에 널 검사를 생성한다** (`/Zc:throwingNew-`가 기본값).
  → "널을 반환하면 즉시 크래시"는 **틀린 서술**이다. 실제로는 생성자를 건너뛰고 `nullptr`이 반환되어
  **조용히 아무 일도 안 일어난다**. 처음에 잘못 썼다가 공식 문서로 바로잡았다.
  출처: <https://learn.microsoft.com/en-us/cpp/build/reference/zc-throwingnew-assume-operator-new-throws>
- **`UnityEngine.Pool.ObjectPool<T>`는 Unity 2021 LTS부터 내장**이다.
  콜백 4종(`createFunc`/`actionOnGet`/`actionOnRelease`/`actionOnDestroy`) + `collectionCheck`/`defaultCapacity`/`maxSize`.
  `maxSize`를 넘겨 반납하면 그 객체는 파괴된다. **`collectionCheck`는 에디터에서만 동작하고 플레이어 빌드에는 없다.**
  **스레드 안전하지 않다**(메인 스레드 전용). `ListPool`/`HashSetPool`/`DictionaryPool`도 있다.
  출처: <https://docs.unity3d.com/6000.4/Documentation/Manual/performance-reusable-code.html>
- **C++17 `<memory_resource>`(PMR)** — `monotonic_buffer_resource`가 범프/아레나 할당자,
  `unsynchronized_pool_resource`가 크기별 풀. 프레임 할당자 패턴의 표준 버전.

### TTT 프로젝트 (바탕화면 `TTT/`) 조사 결과
- **학생 코드가 아니라 외부에서 받은 예제**다. 근거: `TTT.Build.CppClean.log`에 원본 빌드 경로
  `c:\users\dnvmf\onedrive\project\wooprogameproject\...`(다른 사용자 계정, vc142=VS2019)가 남아 있다.
  소스 타임스탬프는 2024-03으로 국비과정 폴더들(2025-12~)보다 앞선다.
  이후 `C:\Study\TTT`에서 v143으로 재빌드 → 2026-07-31에 바탕화면으로 복사됨(`C:\Study\TTT`는 현재 없음).
- 코드의 `std::cout` 추적 출력은 **동작 순서를 눈으로 확인하려고 넣은 학습 흔적**이다.
- **실측 크기(MSVC x64, 직접 컴파일)**: `CTask` 24 / `CMover`·`CEnemy` 56 / `CMyShip` 64 / `CBullet` 72, 정렬 전부 8.
  그런데 세 리스트 모두 슬롯 크기를 **100**으로 줬다 → **100 % 8 == 4라서 홀수 슬롯의 정렬이 깨진다.**
  발견한 결함 중 가장 심각하고 면접 소재로도 가장 좋다.
- 그 외 결함 9건은 C-2의 10절에 전부 정리되어 있다.

### 기존 정리 자료에서 이미 검증된 사실
