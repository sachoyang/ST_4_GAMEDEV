## 이 자료만의 차별화 포인트 5가지

면접에서 **다른 지원자와 갈리는 지점**들. 반드시 숙지할 것.

**① Unity의 GC는 .NET의 GC와 다르다** → [02](02_CSharp.md) Q2-09
대부분의 지원자가 "Gen 0/1/2 세대별 GC"를 말한다. 하지만 **Unity는 Boehm 방식이라 세대 구분이 없고 힙 압축도 하지 않는다.**
그래서 단편화가 누적되고, 힙이 커질수록 GC 시간이 길어진다. **오브젝트 풀링이 Unity에서 특히 중요한 진짜 이유**가 이것이다.

**② SRP Batcher는 드로우 콜을 줄이는 게 아니다** → [03](03_Unity.md) Q3-17
드로우 콜 수가 아니라 **드로우 콜 사이의 렌더 상태 변경 비용**을 줄인다. 이 구분을 정확히 말하면 확실히 앞선다.

**③ Unity의 Fake Null 문제** → [03](03_Unity.md) Q3-25
`Destroy` 후 `== null`은 true인데 `?.`는 실행된다. Unity가 `==`를 오버로딩했지만 **null 조건 연산자는 그걸 무시**하기 때문.

**④ 여러 번의 Deprecated API 마이그레이션 경험** → [03](03_Unity.md) Q3-34
`Application.LoadLevel`→`SceneManager`, `WWW`→`UnityWebRequest`, `[PreferenceItem]`→`[SettingsProvider]`,
Input Manager→New Input System, XR Toolkit 콜백 방식 변경, Built-in RP→URP. **6건을 직접 겪었다.**

**⑤ 같은 문제를 여러 방식으로 다시 풀어본 경험** → [07](07_디자인패턴.md) Q7-04, [08](08_인성_직무.md) 소재 창고 B
FSM 3가지 / A* 실행방식 3단계 / 저장 시스템 3세대 / 암호화 2세대 / 싱글턴 3단계 / 자료구조 3단계.
**"이게 좋다더라"가 아니라 직접 비교한 근거로 선택 이유를 말할 수 있다.**
